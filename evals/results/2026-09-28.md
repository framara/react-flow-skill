## Review and harness corrections

Both agents reported their own TypeScript/browser checks. Independent grading passed in Playwright Chromium 153.0.8010.12 on macOS with the pinned dependencies. The keyboard editor uses controlled state, updates the node's accessible name with the edited label, and provides a visible focus outline; its keyboard-focus screenshot was inspected. The repair app uses immutable node-data updates, controlled change handlers, and source/target handles.

Initial grader development exposed test assumptions, not candidate changes: wrapped select labels required role-based name matching; native select Home/End behavior varied on macOS; typeahead prefixes required independent endpoint choices. The final keyboard path uses native typeahead and Tab/Enter from deliberately opposite starting choices, so preselected defaults cannot make selection checks pass. Screenshots immediately after initial render timed out in both local Chrome and pinned Chromium; the harness now captures the repair screenshot after its verified input interaction. These runs are harness-development evidence, not independent agent retries.

The deliberately broken repair starter compiles and renders but fails the missing-edge, reactive-value, and persistent-drag checks. It ensures a broken app cannot pass merely because the harness launches.

## Reproduce and interpret

Run `npm run check:evals --prefix verification` after the [maintainer setup](../../README.md#maintenance-and-verification). Reports, screenshots, and traces are written under `verification/artifacts/`; CI uploads them. Captured controls make this result reproducible without invoking an agent.

This is two task-level smoke tests with the skill, without a matched no-skill baseline. It does not establish a general success rate or causal improvement, screen-reader conformance, broad framework support, or performance on large graphs. Run new agents for future instruction changes rather than treating replayed controls as new agent evaluations.
